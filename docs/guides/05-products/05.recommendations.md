# Product Recommendations

> Generate product suggestions for a vacancy, then retrieve full, currently available product details through marketplace search.

Product recommendations are available to enabled ATS users. The API accepts partial campaign-shaped vacancy data, creates an asynchronous recommendation job, and returns ranked product IDs with a short reason.

Each request must contain at least one of these candidate-search fields:

- `postingDetails.title`
- `postingDetails.description`
- `postingDetails.workingLocation.city` or `country` that matches a known location
- `targetGroup.industry` with a `vonqId`
- `targetGroup.jobCategory` with a `vonqId`

Education, seniority, experience, employment type and remote-work preference add ranking context. They cannot be used alone.

## Create a Recommendation

```http
POST /v3/products/recommendations/
Content-Type: application/json
X-AUTH-TOKEN: {token}
X-Customer-Id: {customer_id}

{
  "postingDetails": {
    "title": "Senior PHP Developer",
    "description": "Build and maintain Laravel services.",
    "workingLocation": {
      "city": "London",
      "country": "UK",
      "allowsRemoteWork": 1
    }
  },
  "targetGroup": {
    "seniority": [
      {"description": "Mid-Senior level", "vonqId": "3"}
    ],
    "jobCategory": [
      {"description": "Software Development", "vonqId": "6"}
    ]
  },
  "exclude_ids": [
    "2786cbe7-d1ac-52de-a967-7dc8c98836df"
  ]
}
```

Other properties are optional. Taxonomy `vonqId` values are numeric strings. Industry and job-category items require a `vonqId`.

Use `exclude_ids` for products already in the user's basket. Up to 100 product IDs may be supplied; excluded products are removed before candidates are sent to the recommendation model.

The endpoint returns `202 Accepted`:

```json
{
  "id": "5554a985-5d85-4b4e-b402-895c5afaf1c7",
  "status": "queued",
  "created_on": "2026-08-19T10:07:40.743912Z"
}
```

Use the response's `Location` header to poll the job. Identical requests submitted close together may reuse earlier work while still receiving their own request ID.

## Poll the Result

```http
GET /v3/products/recommendations/5554a985-5d85-4b4e-b402-895c5afaf1c7/
X-AUTH-TOKEN: {token}
X-Customer-Id: {customer_id}
```

The status is `queued`, `running`, `completed`, `failed`, or `expired`. A completed response contains the ranked recommendations:

```json
{
  "id": "5554a985-5d85-4b4e-b402-895c5afaf1c7",
  "status": "completed",
  "created_on": "2026-08-19T10:07:40.743912Z",
  "started_on": "2026-08-19T10:07:40.812000Z",
  "completed_on": "2026-08-19T10:07:42.104000Z",
  "product_count": 2,
  "recommendations": [
    {
      "product_id": "product-id-1",
      "title": "Example Job Board - Job Posting",
      "reason": "Its audience and location match the supplied vacancy."
    }
  ]
}
```

`product_count` is the number of returned recommendations. Titles are resolved when the result is retrieved, so they reflect current product data.

## Retrieve Products Through Search

The recommendation response is intentionally small. Use its ID with product search to retrieve full product objects:

```http
GET /products/search/?recommendationId=5554a985-5d85-4b4e-b402-895c5afaf1c7&limit=20&offset=0
X-AUTH-TOKEN: {token}
X-Customer-Id: {customer_id}
```

Search preserves recommendation order, applies pagination after restoring that order, and rechecks current product visibility. It may therefore return fewer products than the original recommendation if a product is no longer available to the ATS user. The recommendation must belong to the authenticated ATS user and be completed.
